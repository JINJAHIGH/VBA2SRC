# VBA2SRC

Officeを起動せず、Excel・Word・AccessファイルからVBAソースと保存情報を読み取り専用で抽出します。
VBAの実行、元ファイルの保護変更、Officeへの書き戻しは行いません。

バージョン1.4.0、JSONスキーマ2。ビルド済みのEXEはPythonやOfficeがないPCでも実行できます。

## 起動方法

ソースの実行とビルドには **Python 3.13 以上** が必要です。
Windows x64 向けのビルド済み [VBA2SRC.exe](https://github.com/JINJAHIGH/VBA2SRC/raw/refs/heads/main/dist/VBA2SRC.exe) をダウンロードできます。

- ファイルをEXEへドラッグ＆ドロップ：対象ファイルと同じフォルダに結果を作成。保存先の質問・ポップアップ・新しいコンソールは表示しません。
- EXEを直接開く：ASCIIタイトルと短い対応形式の案内の後、対象パス・保存先親フォルダ・詳細ログの有無を順に質問します。
- 引数付き起動：1回につき1ファイルを処理します。`--output` を省略すると対象ファイルと同じフォルダに保存します。

```powershell
py -3.13 -m pip install -r requirements.txt
py -3.13 vba2src.py "C:\Work\対象 ファイル (1).xlsm"
py -3.13 vba2src.py "Y:\部門共通\対象.xlsm" -o "Y:\抽出結果" --no-ui --debug-log
.\dist\VBA2SRC.exe "\\server\share\対象.xlsm" --no-ui
py -3.13 vba2src.py "C:\Work\文書.docm" --no-ui
py -3.13 vba2src.py "C:\Work\データベース.accdb" --no-ui
```

| 引数 | 動作 |
| --- | --- |
| `target` | 対象の1ファイル。複数指定はエラー |
| `-o` / `--output` | 結果フォルダを格納する親フォルダ。存在しなければ作成 |
| `--no-ui` | 新しい画面と入力待ちを無効化。既存の標準出力は利用可能 |
| `--debug-log` | 詳細ログと例外スタックを追加。比較用ファイルは変わらない |
| `-h` / `--help` | 使い方 |
| `--version` | バージョン |

相対パスは呼び出し元のカレントフォルダ基準です。書込みに失敗しても別の場所へ自動保存しません。
質問入力では外側の引用符を除去し、空欄の保存先には表示された既定値を使います。`q` で中止します。
引数付き起動は質問しません。`--no-ui` 単独などtargetが不足した起動は終了コード2です。
Windows版は通常起動で新しいコンソールを作らず、必要な場合だけ既存コンソールに接続します。
ポップアップ通知は行いません。結果は利用可能なコンソールと、保存した一覧・ログで確認します。
コンソールは成功を緑、一部成功を黄、失敗を赤で表示し、結果フォルダと最初に読むファイルを分けて案内します。
色は対応する端末だけで使用します。`NO_COLOR`設定時やリダイレクト先・実行ログ・抽出ファイルへはANSI色コードを出しません。
ドラッグ起動等で標準出力がない場合は画面を作らず保存して終了します。結果フォルダ内の`抽出結果一覧.txt`を確認してください。
本体はtkinterを使用せず、配布EXEにもTkを同梱しません。
PowerShellから終了を待つ場合は `Start-Process -Wait -PassThru` を使用できます。

macOSでは `python3 -m pip install -r requirements.txt` の後、`python3 vba2src.py target --no-ui` で起動する構成です。macOS実機では未検証です。

## 設定

[vba2src_config.py](vba2src_config.py) を変更します。

```python
既定保存先親フォルダ = None
VBA保護パスワード候補 = ()

# 設定例
# 既定保存先親フォルダ = r"D:\抽出結果"
# VBA保護パスワード候補 = ("候補1", " 前後空白も含めた候補2 ")
```

既定保存先は**引数なしの対話モードでの初期値**です。通常の引数付き起動では対象ファイルの親を優先します。
None・空文字・存在しないフォルダの場合はツール格納先を使用します。設定の相対パスもツール格納先基準です。
EXEでは実EXEの場所を使用し、PyInstallerの一時展開先は使いません。
候補はVBAプロジェクト保護の検証専用です。Office文書全体の復号には使用しません。
候補の自動生成はなく、空白や大小文字を変えず設定順で照合します。一致した最初の候補だけを結果へ表示します。
候補未設定時は旧方式のパスワードも復元表示しません。不一致候補や生の検証値をログへ出しません。
実際の候補を共有リポジトリへ保存しないでください。**EXEへ設定を反映するには再ビルドが必要**です。

## 出力

親フォルダの下に `対象ファイル名.xlsm_YYYYMMDD_HHMMSS` を作成し、競合時は `_001` 等を付けます。
最初に `抽出結果一覧.txt` を確認してください。コードは `VBAソース/`、日本語項目のJSONは `設定情報/`、実行情報は `ログ/` です。
複数プロジェクトは `プロジェクト/project_001/` 等へ分離します。

JSONの項目名は入れ子を含めて日本語です。例えば `スキーマバージョン`、`プロジェクト識別子`、`名前`、`種類`、`保存ファイル` を使用します。
コメントや説明用の疑似項目は追加しません。**旧スキーマ1の英語キーから変更したため、JSON利用側の修正が必要**です。
元のモジュール名、Attribute、保存参照パス、LIBID等の値は原文を保持します。
UTF-8・BOMなし・LF、JSONは2スペースと固定キー順です。不明は `null`、状態は「設定なし」「読取失敗」「判定不能」「未対応」「対象外」を区別します。
コードはLF化と末尾改行補完だけを行い、コメント・空行・Attributeを保持します。
WinMergeでは結果フォルダ同士を比較し、`ログ/` を除外してください。

セル・範囲等の名前定義は `設定情報/名前定義一覧.json` に保存します。名前、参照先の保存式、ブック／シートの適用範囲、シート名、コメント、非表示フラグ（保存値）、元の順序と属性を保持します。
名前順に整列し、同名ではブック範囲・シート範囲・シート位置で順序を固定します。VBAのないブックも対象です。
対象はXML形式のExcel OOXML（主に.xlsx/.xlsm）。`.xls`（BIFF）と`.xlsb`の名前定義、テーブル名、各セルの値・数式の一覧は未対応です。
名前定義が表す数式・定数・外部参照・`#REF!`は保存文字列として取得し、評価や接続確認は行いません。組み込みの印刷範囲等も除外しません。
`localSheetId`はシート位置（0始まり）として解釈し、保存された`sheetId`と区別します。非表示属性が未保存ならJSONは`null`です。
正常な空一覧は「設定なし」。不正な適用先等があれば回収済み項目を残して「一部取得」とし、確認済みのVBA有無とは分けて終了コード3を返します。
構造の参照資料：[Microsoft Learn DefinedName](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.definedname?view=openxml-3.0.1)。

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 正常。正常なVBAなしも含む |
| 1 | 入出力・暗号化・非対応形式・解析などの致命的失敗 |
| 2 | 引数誤り |
| 3 | 有用な情報を回収したが、必要項目の一部読取りに失敗 |
| 130 | 対話入力の中止、Ctrl+C等 |

候補なし・不一致、完全フォーム復元等の予定範囲外だけでは3にしません。
失敗時も回収結果を残します。書込み途中の失敗ではレポートが未完成の場合があります。

## Windows用EXEの作成

Windows上で実行します。macOSからWindows用EXEは作成しません。

```powershell
py -3.13 -m pip install -r requirements-build.txt
.\scripts\build.ps1
```

ASCIIタイトルの後で `yes` と回答すると、依存確認、ライセンス収集、PyInstallerによるビルド、EXEの起動確認を順に実行します。
依存不足は案内して停止し、自動インストールしません。ログを逐次表示し、進捗率はホストの進捗バーだけに表示します。率は工程に基づく目安です。
百分率を含む文字のバーや「（概算）」の表示はありません。工程見出しはシアン、完了は緑、中止は黄、失敗は赤で表示します。
終了時には結果ブロックへ成果物・停止した工程・ログの場所をまとめます。
ログは `build/logs/`、成果物は `dist/VBA2SRC.exe` です。
`dist/` にLICENSEと第三者ライセンス通知も配置します。ビルド終了コードは正常0、失敗1、中止130です。
`-Python指定` にはバージョン番号（例 `3.15`）や仮想環境の実行ファイル（例 `.venv\Scripts\python.exe`）を指定できます。

実行依存：oletools 0.60.2、olefile 0.47、msoffcrypto-tool 6.1.0、pyOpenVBA 6.6.0。
配布EXEのビルド・確認環境は Windows 11 x64、Python 3.13.18 x64、PyInstaller 6.22.3 です。

## 対応範囲

Excel OOXMLのVBA・VBAなし、OLE内のVBA、Word OOXML／Word 97以降のOLE、Access Jet 4／ACEのMSysAccessStorageを内容で識別します。
Wordは.docm/.dotm/.doc/.dot、VBAなしの.docx/.dotx、Accessは.accdbとAccess 2002以降の保存構造の.mdbが対象です。
共通の取得項目はVBAソース、Attribute、モジュール種類、プロジェクト情報、条件付きコンパイル引数、保存参照設定、VBA保護情報です。
WordのThisDocument、Accessのフォーム／レポートのコードはドキュメントモジュールとして取得します。セル名前定義・シート対応はWord・Accessでは「対象外」です。
ユーザーフォームはコードと一部の保存文字列・コントロール情報を取得します。
完全な.frm/.frx、Accessフォーム／レポートのデザイン・テーブル・クエリ・データ・Accessマクロ、子ストレージフォームの再帰解析、BIFF／XLSBのシート表示名対応、文書全体の復号、PowerPoint、Officeへの書き戻し、XVBA設定生成は未対応です。
Jet 3（Access 97以前）、Access 2000のMSysAccessObjects構造、ソースを削除した.mde/.accdeのソース復元は未対応です。読取不能な形式を「VBAなし」の成功にはしません。
VS CodeでUTF-8コードを閲覧・編集できる出力を提供し、将来の出力アダプター追加を分離できる構成です。
macOS、実SMB共有、Python未導入のクリーンWindows VMは未検証です。SUBSTによる割り当てドライブで入出力を検証しています。

## 保守

本体は `vba2src_app/`、Windows用EXEのビルド処理は `scripts/` にあります。
独自の変数・引数はPythonコード内で日本語化しています。`u16`、`u32`、`width`、`x` 等の明確な短名と外部API名は維持しています。
`names.txt` は使用しません。JSONの項目名定義は `vba2src_app/json_output.py` にあります。
