# VBA2SRC

Officeを起動せず、Excel・Word・AccessファイルからVBAソースと保存情報を読み取り専用で抽出します。
VBAの実行、元ファイルの保護変更、Officeへの書き戻しは行いません。

バージョン1.6.2、JSONスキーマ2。ビルド済みのEXEはPythonやOfficeがないPCでも実行できます。

## 起動方法

ソースの実行とビルドには **Python 3.13 以上** が必要です。
Windows x64 向けのビルド済み [VBA2SRC.exe](https://github.com/JINJAHIGH/VBA2SRC/raw/refs/heads/main/dist/VBA2SRC.exe) をダウンロードできます。

出力仕様、AI に渡すファイルの選び方、VBA からの起動と JSON 解析は [AI・連携ツール向け仕様](docs/AI_GUIDE.md) を参照してください。

### GUI

EXEを直接開くか、引数なしで `python vba2src.py` を実行します。

- **VBAを抽出** で対象のOfficeファイルを入力、参照、または対象欄にドラッグ＆ドロップします。出力先を空欄にすると対象ファイルの隣へ保存します。「モジュール別テキストファイル生成」や詳細ログが必要な場合は、対応するスイッチをオンにします。
- **抽出結果を確認** では、概要、VBAソース、参照設定、条件付きコンパイル引数、名前定義、フォーム、保存ファイルを確認できます。一覧の行を選ぶと詳細が開きます。概要では、VBA保護が「あり」の場合に VBAパスワードを表示します。
- 保存済みの結果は「結果フォルダ」から開けます。旧バージョンの `設定情報/` 形式（JSONスキーマ2）も読み込めます。複数プロジェクトはプロジェクト欄で切り替えます。

GUIはTkinterと [Azure-ttk-theme](https://github.com/rdbende/Azure-ttk-theme) を使用します。Windows配布EXEにはTkとテーマを同梱しています。

### ドラッグ＆ドロップとCLI

OfficeファイルをEXEへドロップすると、そのファイルの隣に結果を保存します。
引数付き起動は1回につき1ファイルを処理し、`--output` の省略時は対象ファイルの親へ保存します。

```powershell
python -m pip install -r requirements.txt
python vba2src.py
python vba2src.py "C:\Work\対象 ファイル (1).xlsm"
python vba2src.py "Y:\部門共通\対象.xlsm" -o "Y:\抽出結果" --no-ui --debug-log
.\dist\VBA2SRC.exe "\\server\share\対象.xlsm" --no-ui
```

| 引数 | 動作 |
| --- | --- |
| `target` | 対象の1ファイル。複数指定はエラー |
| `-o` / `--output` | 結果フォルダを格納する親フォルダ。存在しなければ作成 |
| `--no-ui` | 画面なしの実行を明示。引数付き起動は省略時も画面なし |
| `--debug-log` | `ログ/実行ログ.txt` に詳細情報を保存 |
| `--group-by-type` | 通常の出力に加えて `VBAまとめ/` にモジュールの種類別テキストを保存 |
| `-h` / `--help` | 使い方 |
| `--version` | バージョン |

相対パスは呼び出し元のカレントフォルダ基準です。引数付き起動の結果は、利用可能なコンソールと `入力情報.json` で確認できます。
端末表示は `NO_COLOR` の設定に対応します。PowerShellから終了を待つ場合は `Start-Process -Wait -PassThru` を使用できます。

ソースからGUIを起動する場合はTkinterを含むPythonを使用してください。macOS実機では未検証です。

## 設定

ウィンドウ右上の「設定」を開きます。「保存」を押すと、その場で設定を反映し、次回起動時も使用します。

- **基本** ではGUIで使う既定の出力先と、画面・コード表示それぞれのフォントとサイズを指定します。
  画面フォントの自動設定では BIZ UDPゴシックを使用します。
  VBAコードの自動設定は MS ゴシック 10 pt を優先します。
- **VBA保護** では公開用の既定候補（`AAADEV`、`AAAPAS`、`BBBDEV`）を初期表示します。
  候補は空白と大小文字を保持し、一覧の上から順に照合します。候補はそのまま追加・更新・削除できます。候補を使わないときは一覧を空にします。「リセット」で候補だけを初期値に戻します。
- **既定値に戻す** で初期値を呼び出せます。反映するには「保存」を押します。

Windowsの設定ファイルは `%TEMP%\VBA2SRC\settings.json` です。OSが一時ファイルを削除した場合は初期値に戻ります。
登録した候補は同ファイルに平文で保存します。候補の設定はGUI、ドラッグ＆ドロップ、CLIの抽出で共通です。
候補照合は既存のVBAプロジェクト保護情報に対して行います。一致した最初の候補を `保護情報.json` に記録します。

「既定の出力先」を指定すると、GUI起動時の「出力先フォルダ」に入ります。どちらも空欄なら対象ファイルと同じフォルダへ保存します。
CLIの保存先は `--output` または対象ファイルの親です。

## 出力

親フォルダの下に `対象ファイル名.xlsm_YYYYMMDD_HHMMSS` を作成し、競合時は `_001` 等を付けます。
`入力情報.json` で抽出状態とVBAの有無を確認できます。VBAの各種設定JSONは `VBAソース/` と同じ階層に保存します。
フォームのコード `フォーム名.txt` とフォーム情報 `フォーム名.json` は `VBAソース/ユーザーフォーム/` に並びます。
複数プロジェクトのコードと固有の設定は、`プロジェクト/project_001/` 等に分かれます。
`ログ/` は、CLIの `--debug-log` またはGUIの対応するスイッチを選んだ実行で作成します。

JSONの項目名は入れ子を含めて日本語です。例えば `スキーマバージョン`、`プロジェクト識別子`、`名前`、`種類`、`保存ファイル` を使用します。
コメントや説明用の疑似項目は追加しません。**旧スキーマ1の英語キーから変更したため、JSON利用側の修正が必要**です。
元のモジュール名、Attribute、保存参照パス、LIBID等の値は原文を保持します。
UTF-8・BOMなし・LF、JSONは2スペースと固定キー順です。不明は `null`、状態は「設定なし」「読取失敗」「判定不能」「未対応」「対象外」を区別します。
コードはLF化と末尾改行補完だけを行い、コメント・空行・Attributeを保持します。
詳細ログを有効にした結果をWinMergeで比較する場合は、`ログ/` を除外してください。

セル・範囲等の名前定義は `名前定義一覧.json` に保存します。名前、参照先の保存式、ブック／シートの適用範囲、シート名、コメント、非表示フラグ（保存値）、元の順序と属性を保持します。
名前順に整列し、同名ではブック範囲・シート範囲・シート位置で順序を固定します。VBAのないブックも対象です。
対象はXML形式のExcel OOXML（主に.xlsx/.xlsm）。`.xls`（BIFF）と`.xlsb`の名前定義、テーブル名、各セルの値・数式の一覧は未対応です。
名前定義が表す数式・定数・外部参照・`#REF!`は保存文字列として取得し、評価や接続確認は行いません。組み込みの印刷範囲等も除外しません。
`localSheetId`はシート位置（0始まり）として解釈し、保存された`sheetId`と区別します。非表示属性が未保存ならJSONは`null`です。
正常な空一覧は「設定なし」。不正な適用先等があれば回収済み項目を残して「一部取得」とし、確認済みのVBA有無とは分けて終了コード3を返します。
構造の参照資料：[Microsoft Learn DefinedName](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.definedname?view=openxml-3.0.1)。

### VBAコードを種類別にまとめる

AIに渡すファイル数を減らすには `--group-by-type` を指定します。

```powershell
python vba2src.py "C:\Work\対象.xlsm" --group-by-type --no-ui
.\dist\VBA2SRC.exe "C:\Work\対象.xlsm" --group-by-type --no-ui
```

結果フォルダ直下の `VBAまとめ/` に、取得できたコードがある種類だけ一つずつテキストファイルを作ります。
ファイル名は `標準モジュール.txt`、`フォーム.txt`、`クラスモジュール.txt`、`ドキュメントモジュール.txt`、`未分類.txt` です。

同じ種類のコードは複数のVBAプロジェクトにまたがって一つのファイルに収録します。各章の先頭に、元のモジュール名とプロジェクト識別子を付けます。

```vb
' ===== モジュール：集計処理（プロジェクト：project_001） =====
```

各章はコメント、空行、Attributeを含む抽出済みコードをそのまま収録し、UTF-8（BOMなし）・LFで保存します。VBAがない場合など、コードが一つも取得できなければ `VBAまとめ/` は空になります。

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 正常。正常なVBAなしも含む |
| 1 | 入出力・暗号化・非対応形式・解析などの致命的失敗 |
| 2 | 引数誤り |
| 3 | 有用な情報を回収したが、必要項目の一部読取りに失敗 |
| 130 | Ctrl+C等による中止 |

候補なし・不一致、完全フォーム復元等の予定範囲外だけでは3にしません。
失敗時も回収結果を残します。書込み途中の失敗ではJSONやソースが未完成の場合があります。

## Windows用EXEの作成

Windows上で実行します。macOSからWindows用EXEは作成しません。

```powershell
.\scripts\build.ps1
```

ASCIIタイトルの後で `yes` と回答すると、使用する Python と pip で依存関係を確認します。
追加やバージョン変更が必要なライブラリは、間接依存も含めて一件ずつ名前とバージョンを表示します。すべてに `yes` と回答すると導入し、一件でも辞退すると中止します。
依存関係の確認後、ライセンス収集、PyInstallerによるビルド、EXEの起動確認を順に実行します。ログを逐次表示し、進捗率はホストの進捗バーだけに表示します。率は工程に基づく目安です。
百分率を含む文字のバーや「（概算）」の表示はありません。工程見出しはシアン、完了は緑、中止は黄、失敗は赤で表示します。
終了時には結果ブロックへ成果物・停止した工程・ログの場所をまとめます。
ログは `build/logs/`、成果物は `dist/VBA2SRC.exe` です。
`dist/` にLICENSEと第三者ライセンス通知も配置します。ビルド終了コードは正常0、失敗1、中止130です。
既定では PATH 上の `python` を使用します。`-Python指定` には Python ランチャーで選ぶバージョン番号（例 `3.13`）や、仮想環境の実行ファイル（例 `.venv\Scripts\python.exe`）を指定できます。

実行依存：oletools 0.60.2、olefile 0.47、msoffcrypto-tool 6.1.0、pyOpenVBA 6.6.0、tkinterdnd2 0.7.0（GUIのファイルドロップ）。
配布EXEのビルド・確認環境は Windows 11 x64、Python 3.15.2 x64、PyInstaller 6.22.3 です。

## 対応範囲

Excel OOXMLのVBA・VBAなし、OLE内のVBA、Word OOXML／Word 97以降のOLE、Access Jet 4／ACEのMSysAccessStorageを内容で識別します。
Wordは.docm/.dotm/.doc/.dot、VBAなしの.docx/.dotx、Accessは.accdbとAccess 2002以降の保存構造の.mdbが対象です。
共通の取得項目はVBAソース、Attribute、モジュール種類、プロジェクト情報、条件付きコンパイル引数、保存参照設定、VBA保護情報です。
WordのThisDocument、Accessのフォーム／レポートのコードはドキュメントモジュールとして取得します。セル名前定義・シート対応はWord・Accessでは「対象外」です。
ユーザーフォームはコードと一部の保存文字列・コントロール情報を取得します。
完全な.frm/.frx、Accessフォーム／レポートのデザイン・テーブル・クエリ・データ・Accessマクロ、子ストレージフォームの再帰解析、BIFF／XLSBのシート表示名対応、文書全体の復号、PowerPoint、Officeへの書き戻し、XVBA設定生成は未対応です。
Jet 3（Access 97以前）、Access 2000のMSysAccessObjects構造、ソースを削除した.mde/.accdeのソース復元は未対応です。読取不能な形式を「VBAなし」の成功にはしません。
VS CodeでUTF-8コードを閲覧・編集できる出力を提供し、将来の出力アダプター追加を分離できる構成です。
macOS、実SMB共有、Python未導入のクリーンWindows VMは未検証です。SUBSTによる割り当てドライブで入出力を検証しています。

## 保守

本体は `vba2src_app/`、Windows用EXEのビルド処理は `scripts/` にあります。
独自の変数・引数はPythonコード内で日本語化しています。`u16`、`u32`、`width`、`x` 等の明確な短名と外部API名は維持しています。
`names.txt` は使用しません。JSONの項目名定義は `vba2src_app/json_output.py` にあります。
